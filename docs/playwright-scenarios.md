# Playwright 검사 시나리오 모음

체스리엔드 주요 사용자 흐름에 대한 Playwright 검사 프롬프트. 클로드에게 그대로 붙여넣어 실행시킬 수 있는 형태로 작성.

진행 규칙은 `.claude/rules/playwright.md` 참조.

---

## 공통 사전 조건

모든 시나리오 실행 전 다음이 떠 있어야 함:

- PostgreSQL: `docker compose up -d postgres`
- Backend: `./gradlew bootRun` (http://localhost:8080)
- Frontend: `cd frontend && pnpm dev` (http://localhost:5173)

---

## 1. PGN 가져오기 — chess.com

**프롬프트:**

> Playwright로 다음을 검사해줘.
>
> - **목표**: chess.com 유저명으로 게임 가져오기 → 게임 리스트에 표시되는지 확인
> - **시작 상태**: http://localhost:5173/import, 로그인 불필요
> - **입력**: chess.com 유저명 `hikaru` (또는 사용자가 지정한 유저명), 최근 5게임
> - **순서**:
>   1. /import 페이지 진입
>   2. 플랫폼 "chess.com" 선택
>   3. 유저명 입력 후 가져오기 버튼 클릭
>   4. 진행 표시(스피너) 확인
>   5. /games로 이동되거나 게임 리스트에 새 게임이 추가되는지 확인
> - **성공 조건**: 게임 카드가 최소 1개 렌더되고 흰말/검은말 닉네임이 표시됨
> - **실패 신호**: 에러 토스트, 빈 리스트, 콘솔에 4xx/5xx 네트워크 에러
> - **보고**: 게임 리스트 스크린샷, 가져온 게임 수, 네트워크 요청 중 `/api/games/import` 응답 상태

## 3. 게임 상세 보기 + 수 네비게이션

**프롬프트:**

> Playwright로 다음을 검사해줘.
>
> - **목표**: 게임 상세 페이지에서 수 이동이 보드/EvalBar에 반영되는지
> - **시작 상태**: /games에 게임이 최소 1개 있음 (없으면 시나리오 1 먼저)
> - **순서**:
>   1. /games 첫 번째 게임 카드 클릭 → /games/:id 진입
>   2. 보드가 시작 포지션으로 렌더되는지 확인
>   3. 다음 수 버튼(또는 → 키) 5번 클릭
>   4. 각 클릭마다 보드 말 위치가 변하는지 스냅샷
>   5. 이전 수 버튼으로 3번 되돌리기
> - **성공 조건**: 보드 FEN이 매번 갱신, 무브 리스트의 하이라이트가 따라 움직임
> - **실패 신호**: 보드가 멈춤, 콘솔 에러, EvalBar가 NaN
> - **보고**: 시작/중간/되돌린 후 3장 스크린샷

## 4. Stockfish 분석 + EvalBar 캐시 재사용

**프롬프트:**

> Playwright로 다음을 검사해줘.
>
> - **목표**: 이미 분석된 게임을 다시 열었을 때 Stockfish 재실행 없이 캐시된 평가가 즉시 나오는지
> - **시작 상태**: /games/:id (이미 분석 완료된 게임 — 분류 라벨 Brilliant/Blunder 등이 보이는 것)
> - **순서**:
>   1. 게임 진입 후 EvalBar가 즉시(<500ms) 평가 값 표시하는지 확인
>   2. 콘솔에서 Stockfish 워커 메시지가 새로 출력되지 않는지 모니터링 (`browser_console_messages`)
>   3. 수 네비게이션 5번 — 각 수마다 EvalBar 값이 캐시에서 즉시 갱신되는지
> - **성공 조건**: EvalBar 갱신은 즉시, 콘솔에 `uci go` / `bestmove` 류 새 로그 없음
> - **실패 신호**: 각 수마다 분석 스피너가 다시 뜸, 콘솔에 Stockfish 워커 새 시작 로그
> - **보고**: 콘솔 로그 전체, EvalBar 갱신 타이밍

## 5. 메모 저장 + 새로고침 후 유지

**프롬프트:**

> Playwright로 다음을 검사해줘.
>
> - **목표**: 특정 수에서 메모를 작성하고 저장한 후, 새로고침해도 유지되는지
> - **시작 상태**: /games/:id (게임 1개)
> - **입력**: 메모 내용 `테스트 메모 - {현재 시각}`
> - **순서**:
>   1. 5번째 수로 이동
>   2. 메모 입력 영역에 텍스트 입력
>   3. 저장 버튼 클릭 → 성공 토스트 또는 인디케이터 확인
>   4. `browser_navigate`로 같은 URL 새로고침
>   5. 같은 수로 다시 이동해서 메모가 그대로 있는지 확인
> - **성공 조건**: 새로고침 후에도 입력한 텍스트가 메모 영역에 표시
> - **실패 신호**: 메모가 빈칸, 저장 실패 토스트, 콘솔에 PUT/POST 실패 로그
> - **보고**: 저장 전/저장 후/새로고침 후 3장 스크린샷, 메모 저장 API 응답 상태

## 6. 게임 분류 라벨 표시 (Brilliant / Blunder 등)

**프롬프트:**

> Playwright로 다음을 검사해줘.
>
> - **목표**: 분석 완료된 게임에서 각 수에 분류 라벨이 표시되고 색상이 규약(red/orange/yellow 등)과 일치하는지
> - **시작 상태**: 분석된 게임 /games/:id
> - **순서**:
>   1. 무브 리스트 스크롤하면서 라벨이 붙은 수들을 찾기
>   2. 각 라벨의 클래스/색상이 `.claude/rules/ui.md` "Classification" 색상과 일치하는지 (Blunder=red, Mistake=orange, Inaccuracy=yellow, Brilliant=별도 아이콘/색)
>   3. 라벨이 붙은 수를 클릭 → 보드 이동 + EvalBar 변화 확인
> - **성공 조건**: 모든 라벨 색상이 규약대로, 클릭 시 보드 동기화
> - **실패 신호**: 색상 불일치, 클릭해도 보드 안 움직임
> - **보고**: 무브 리스트 스크린샷, 발견된 라벨 종류 카운트

## 7. 다크 모드 토글

**프롬프트:**

> Playwright로 다음을 검사해줘.
>
> - **목표**: 다크 모드 토글이 모든 인터랙티브 요소에 적용되는지
> - **시작 상태**: 아무 페이지
> - **순서**:
>   1. 라이트 모드 스크린샷
>   2. 토글 클릭
>   3. 다크 모드 스크린샷
>   4. /games, /games/:id, /import 각각에서도 동일 확인
> - **성공 조건**: 배경/텍스트/카드/버튼이 모두 다크 톤으로 전환, 대비 충분
> - **실패 신호**: 일부 요소만 라이트 모드 잔존, 흰 배경에 흰 글씨 같은 가독성 문제
> - **보고**: 페이지당 라이트/다크 2장씩 스크린샷

## 새 시나리오 추가 가이드

위 7개 섹션 골격(`목표 / 시작 상태 / 입력 / 순서 / 성공 조건 / 실패 신호 / 보고`)을 따라 작성한다. 클로드가 사용자 의도를 추측하지 않고 곧바로 실행할 수 있어야 한다.
